# Third-Party Asset Policy

The rules for any asset (model, texture, audio, font, icon, shader, data) not originally created for Oathbound. Goal: **legal safety and clear provenance**, with a hard wall against any Hordes.io IP. Every external asset is logged in the registry: [THIRD_PARTY_ASSETS.md](./THIRD_PARTY_ASSETS.md). **No assets were downloaded during planning.**

## Allowed license types (in order of preference)
1. **Original procedural** assets (generated by our code) — no license concern.
2. **Original commissioned/authored** assets (we own them).
3. **CC0 / public domain** — preferred external option (no attribution burden).
4. **Clearly-licensed commercial-use** assets (e.g., permissive licenses) — only if terms are unambiguous and compatible.

## Use with caution
- **Attribution-required** licenses (e.g., CC-BY): permitted **only** if we can and do satisfy attribution in-product + registry. Track the exact requirement.
- Anything with **share-alike**, **non-commercial**, **no-derivatives**, or ambiguous terms → **avoid** unless explicitly cleared.

## Hard prohibitions
- **No assets of unclear ownership or license.**
- **Never rip, extract, trace, or recreate proprietary Hordes.io assets** — models, textures, audio, icons, UI, or visual identity. Hordes.io is a **design reference only** ([HORDES_IO_ANALYSIS](../research/HORDES_IO_ANALYSIS.md)).
- No copying Hordes.io (or any other game's) **names, classes-as-named, world, maps, monsters, lore, ability/item names, UI, icons, or balancing values**.
- No assets that embed third-party trademarks/logos.

## Before any asset enters the repo (checklist)
- [ ] License identified and **compatible** with a commercial-capable browser game.
- [ ] Source URL + creator recorded.
- [ ] Attribution requirement noted (and a plan to satisfy it, if any).
- [ ] Any modifications recorded.
- [ ] File location + date acquired recorded.
- [ ] Added to [THIRD_PARTY_ASSETS.md](./THIRD_PARTY_ASSETS.md) **with all fields filled**.
- [ ] If in doubt → **do not use it**; prefer procedural/original.

## Registry requirement (every external asset)
The registry must capture, per asset: **name · source · creator · license · license URL · attribution requirement · modifications · file location · date acquired.** An asset without a complete registry entry is not permitted in a build. CI/asset review checks this (R20 — [RISK_REGISTER](../production/RISK_REGISTER.md)).

## Attribution delivery
If any attribution-required assets are used, the game ships a **Credits/Licenses** screen (and/or a bundled `LICENSES` file) listing each, generated from the registry. Keeping the registry authoritative makes this automatic.

## Fonts, icons, audio specifics
- **Fonts:** use OFL/CC0/clearly-licensed web fonts only.
- **Icons:** original or CC0 icon sets; no game-ripped icons.
- **Audio:** CC0/public-domain SFX libraries or original recordings/synthesis; verify the *specific file's* license (pack-level claims aren't enough).

## Why this matters
A browser game deployed publicly is a distribution. Unclear licensing is a real legal and reputational risk (R20). The policy keeps Oathbound shippable and ethical, and the **procedural-first** [ASSET_PIPELINE](./ASSET_PIPELINE.md) minimizes external dependence in the first place.
