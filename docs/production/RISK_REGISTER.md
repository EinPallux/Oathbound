# Risk Register

Every significant project risk with **Probability (P)**, **Impact (I)** (both Low/Med/High), **warning signs**, **prevention**, **mitigation**, and the **roadmap phase where it must be reviewed**. Reviewed at the named [VERSION_ROADMAP](./VERSION_ROADMAP.md) band and re-checked at each [release gate](./RELEASE_GATES.md).

## Top-5 watchlist (review at every gate)
**R1 Scope creep · R2 Repetitive combat · R4 Three.js performance · R8/R9/R10/R11 Class balance · R24 World-before-combat.** These most threaten the core thesis (a *fun, performant, solo* loop) and are explicitly re-checked at each [release gate](./RELEASE_GATES.md).

## How risks connect to gates
A gate fails if its associated risk has materialized (e.g., the Core Loop Gate fails if R2 shows in playtest; the Three-Class Gate fails if R8–R11 show in TTK data). Risks are therefore not just a list — they are the *reasons* gates exist.
